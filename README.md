# MBTI 16 型人格测试 H5 🧠

纯前端 MBTI 性格测试 H5：**64 题题库，每次随机抽 32 题**（四个维度各 8 题），每题 **4 个选项**（强烈 / 轻微两档），加权计分，
输出 16 型人格结果 + 四维倾向百分比 + 倾向强度 + 结果一致性分析。
零依赖、零后端，题目与结果全部为静态 JSON，可直接发布到 GitHub Pages。

> 每次打开都是不同的题目组合：**随机抽题 + 选项顺序打乱 + 整卷题目乱序**。适合反复测，也适合分享给朋友「对答案」。

## 项目结构

```
mbti-test-h5/
├── index.html            # 页面骨架（封面 / 答题 / 分析中 / 结果报告）
├── css/style.css         # 移动端优先样式（375px 视口，无横向溢出）
├── js/app.js             # 全部逻辑：随机组卷、加权计分、维度分析、一致性、分享
├── test/smoke-test.js    # Node 冒烟测试（无需浏览器、无依赖）
└── data/
    ├── questions.json    # 64 题题库（E/I、S/N、T/F、J/P 各 16 题，每题 4 个选项）
    ├── results.json      # 16 型人格（名称/标签/总结/优势/盲点/职业/关系匹配/配色）
    └── dimensions.json   # 8 个维度两极的解读文案
```

## 测试设计要点

### 随机组卷

- **题库 64 题**，四个维度各 16 题；每次测试**从每个维度随机抽 8 题**，共 32 题。
- 每题 4 个选项的顺序**独立打乱**，整卷 32 题的**题目顺序也打乱**（避免同维度的题扎堆出现，减少答题惯性）。
- 随机性带来的量化效果（5000 次模拟）：

  | 指标 | 数值 |
  |---|---|
  | 单题被抽中概率 | 0.500（每维 16 题抽 8 题） |
  | 两次测试的平均重合题数 | 16 题 / 32 题 |
  | 连测 3 次平均覆盖题数 | 55.9 题 / 64 题（约 87%） |

  → 意思是：**同一个人两次测到的题有一半不同**，复测不容易「记住答案」，适合做对照。

### 计分与判定

- **加权计分**：每个选项带 `weight`，选「强烈」计 2 分、选「轻微」计 1 分。倾向百分比 = 该极得分 ÷ 两极总分。
  这比简单的 2 选 1 计数更细腻，也避免「只要偏向一极，强弱都被算成一样」。
- **平局兜底**：加权后仍可能平局，按 `I / N / F / P` 兜底（见 `js/app.js` 的 `TIE_BREAK`），并在结果页提示「两个倾向非常接近」。
- **倾向强度**：按答案偏向幅度自动标注「非常明显 / 比较明显 / 轻微倾向 / 无明显倾向」。
- **结果一致性**：四个维度偏向幅度的平均值，输出「很高 / 中等 / 偏低」，提示是否处于变化期或本身就擅长切换。
- **四维解读**：结果页按各维度主导字母，展示该极的定义与关键词。

## 冒烟测试

`test/smoke-test.js` 用最小 DOM 桩在 Node 里跑完整流程（封面 → 32 题 → 结果页），
无需浏览器、无需安装任何依赖：

```bash
node test/smoke-test.js                            # 正常路径，校验结果页各区块
SMOKE_FAULT=groups       node test/smoke-test.js   # results.json 缺 groups（应降级且不报错）
SMOKE_FAULT=missing-type node test/smoke-test.js   # 结果库缺类型（应进入兜底页，不卡 loading）
SMOKE_FAULT=nodata       node test/smoke-test.js   # 数据加载失败（应提示改用 HTTP 打开）
```

除结果页各区块外，它还专门锁住几个「容易悄悄坏掉」的地方：

- **随机组卷**：每次恰好 32 题、四维各 8 题、卷内无重复题、每题选项内容完整无丢失
- **加权计分**：用「强左 / 弱左 / 弱右 / 弱右」模式作答，每维应得 60% : 40%。
  若计分被改回简单计数，结果会退化成 4:4 平局（INFP）而不是 ESTJ，测试立刻报错
- **随机性**：重新测试后题目序列必须发生变化
- **不会卡 loading**：即使结果库缺类型，也必须落到兜底页

> 改动 `js/app.js` 或 `data/*.json` 后建议先跑一遍，避免再次出现「结果页渲染异常导致一直卡在分析中」。

## 容错设计（为什么要跑上面的测试）

- 分析动画结束后，`renderResult()` 被 `try/catch` 包裹，**无论成功失败都会离开加载页**。
- 四维倾向图、维度解读、一致性分析**不依赖结果库**，先渲染；结果详情单独渲染，出问题只影响详情区块。
- 结果库缺少对应类型时，进入兜底页并保留已算出的四维分析，同时提示检查数据文件。

## 二次修改

- **改题目**：`data/questions.json`。每题 4 个选项，字段要求：
  - `score` 填该选项所属字母（E/I/S/N/T/F/J/P），**同题 4 个选项必须只涉及同一维度的两个字母**；
  - `weight` 为计分权重（强烈填 `2`、轻微填 `1`），建议保持「2,1,1,2」的强弱结构；
  - **题干文本需全局唯一**（否则随机组卷时可能抽到两道标题一样的题，测试会报错）；
  - `perDimension` 控制每次每维抽多少题（当前 8）。若某维度题数少于该值，该维度会只出全部题（不会崩，但维度占比会失衡）。
- **改题库规模**：想加题就按维度往 `questions.json` 里追加，每维题数决定复测时的新鲜度——每维 16 题、抽 8 题时，两次测试重合约一半。
- **改结果文案**：`data/results.json`，16 个 `code` 需覆盖全部组合，否则会兜底显示 INTJ。
- **改维度解读**：`data/dimensions.json`，`poles` 需含全部 8 个字母。
- **改分享文案**：`data/results.json` 顶部 `shareTemplate`，支持 `{code}` `{name}` `{tagline}`。
